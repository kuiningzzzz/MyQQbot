# 定时任务

定时模块在 admin“功能管理 → 定时任务”中启用，所有时间统一使用北京时间。固定消息不依赖 AI；AI 任务需要 AI 服务及聊天开关开启、模型环境变量配置有效。

## QQ 指令

群聊和私聊使用相同指令。固定消息使用 `/timing-task`，AI 提示词使用 `/timing-task-AI`。

| 选项 | 循环 | 时间格式 | 示例 |
| --- | --- | --- | --- |
| `-y` | 每年 | `MM-DD-HH-MM-SS` | `10-01-00-00-00` |
| `-m` | 每月 | `DD-HH-MM-SS` | `01-08-00-00` |
| `-w` | 每周 | `DD-HH-MM-SS`，01周一至07周日 | `01-08-00-00` |
| `-d` | 每天 | `HH-MM-SS` | `08-00-00` |
| `-o` | 仅一次 | `YY-MM-DD-HH-MM-SS`，也支持四位年份 | `2027-01-01-00-00-00` |

两位年份解释为2000至2099年。循环任务的本周期时间已过时，自动安排下一次，例如上午10点新增“每天8点”，从明天8点开始。一次性时间必须晚于当前时间，否则回复：

> 我只是个小破机器人，不可以回溯时空哦！

每月31号遇到没有31号的月份会跳过该月；每年2月29号会跳到下一个闰年，不自动改成其他日期。

### 中国农历

选项加 `-cn` 后缀即可，固定消息、AI任务和Agent工具均支持，时分秒仍按北京时间：

| 选项 | 含义 | 时间格式 |
| --- | --- | --- |
| `-y-cn` | 每农历年同一月日，如农历生日 | `MM-DD-HH-MM-SS` |
| `-m-cn` | 每个农历月同一日，包含闰月 | `DD-HH-MM-SS` |
| `-o-cn` | 指定农历日期，仅一次 | `YY-MM-DD-HH-MM-SS`，也支持四位年份 |
| `-w-cn` / `-d-cn` | 与每周 / 每天相同 | 与原选项相同 |

农历月份用01至12、日期用01至30，支持1900至2100年。年循环只在普通月份提醒一次，不在同名闰月重复；月循环包含闰月。没有三十日的月份会跳过，不自动提前到二十九。数字年份也是农历年份，例如 `2027-01-01` 表示农历2027年正月初一。循环本期已过自动安排下一次，过去的一次性日期仍拒绝创建。admin可选择历法及循环，创建回执和列表同时展示对应公历执行时间与农历日期。

```text
/timing-task -y-cn 08-15-00-00-00 农历生日快乐！
/timing-task -m-cn 01-08-00-00 今天是农历初一
/timing-task-AI -y-cn 01-01-08-00-00 生成一份春节祝福，结合本群兴趣并发送
/timing-task -o-cn 2027-01-01-00-00-00 春节快乐！
```

农历转换使用本地依赖 [lunar-python](https://github.com/6tail/lunar-python)，运行时无需联网查询日历。原有不带-cn的任务仍按公历运行，现有数据无需迁移。

### 使用示例

```text
/timing-task -y 10-01-00-00-00 纪念日快乐！
/timing-task -d 18-00-00 下班记得带钥匙
/timing-task -w 05-20-00-00 周五晚上来打游戏
/timing-task-AI -d 08-00-00 播报今日新闻，优先关注本群公开讨论和记忆中的兴趣，附来源链接
/timing-task-AI -d 02-00-00 整合所有新增记忆，使用integrate_memory处理到pending为0；不要发送QQ消息
```

消息正文和提示词会保留大小写、空格和换行。群里可通过QQ客户端选择真正的艾特群友，将它放在时间后的正文中；宿主保存原生 at 消息段，发送时仍会艾特。只支持文字和艾特具体QQ号，不支持图片、引用、其他消息段或艾特全体。私聊中的艾特会显示为普通 `@QQ号` 文字。

```text
/timing-task list
/timing-task-AI list
/timing-task del 任务ID
/timing-task-AI del 任务ID
```

list 以 QQ 聊天记录形式列出当前会话相应类型的全部任务，每条任务一个节点，显示完整创建指令、唯一ID和下次时间。每张卡片最多99条，超出后继续发送。已完成的一次性任务会保留为停用状态，便于查看及删除。

任意群友可以管理本群的任务，不限创建者；群A无法查看、删除或设置群B任务。私聊只管理该私聊自己的任务，与任何群聊隔离。del 不能跨固定消息/AI类型删除。

## 自然语言与权限

可以对机器人说“每天18点提醒我带钥匙”“每天早上8点在这里播报新闻”“列出这里所有定时任务”“把编号……的提醒改到19点”“删除编号……的任务”。主对话会 Spawn 一次性执行者，由执行者调用以下工具：

- `schedule_create(flag,time,kind?,content?,prompt?,delivery?)`
- `schedule_list(kind?)`
- `schedule_update(task_id,flag?,time?,content?,prompt?,delivery?,enabled?)`
- `schedule_delete(task_id)`

确定的定时任务文本使用 `/timing-task`：创建时传 `kind="fixed"` 和 `content`，到时直接发送保存的正文，不调用AI。需要执行时动态获取或AI生成的文本、任务处理使用 `/timing-task-AI`：传 `kind="ai"` 和 `prompt`；省略kind默认ai，兼容原有调用。固定正文保留空格、换行，支持 `[CQ:at,qq=123456]` 群聊艾特，私聊转换为普通 `@123456` 文字；固定任务不接受prompt或delivery，AI任务不接受content。

list省略kind返回两类任务，也可传fixed或ai筛选。update/delete使用查询获得的task_id；update保持原类型，修改固定正文传content，修改AI提示词传prompt，enabled支持暂停/启用。只修改时间或开关时，原正文和艾特保留。

这些工具可增删改查当前QQ会话的固定消息和AI任务，不能指定其他会话、伪造请求者或指定主人授权。工具会返回真实保存的任务ID和下次时间，AI不能只口头答应。日期/时刻不清楚时应先澄清。QQ指令仍按各自类型创建、list和del，原有发送逻辑不变。

AI任务的执行身份来自真实创建者或最后修改者。仅主人本人创建/修改的任务可以获得主人权限；普通群友修改原主人任务会重新计算身份并撤销主人授权。更换主人后，旧主人授权任务不能继续越界执行。

## AI 运行机制

本项目锁定的 dsh 版本有 schedule 插件，但它要求 Web Session controller，并默认向原会话投递；这里采用 Python 持久化调度和 dsh 原生 fork，保持现有独立内核运行方式与秒级日期格式。

每次触发使用 `ctx.subagents.start('fork', ...)` 从共享主聊天的**已完成回合**复制历史，注入以 `[定时任务]` 开头的本次提示。正在处理中的主回合和后来新增的聊天不会进入该分支。任务独立执行，主对话可同时接待消息，任务结果不续写主对话。

定时分支直接使用 dsh 原生文件、搜索、记忆SKILL和本会话QQ工具，不能再 Spawn。身份、场景和权限重新由宿主注入，不能继承历史中的主人权限。任务完成或取消后，释放原生句柄并删除分支日志；文件效果保留。意外退出会留下清理凭据，下次启动内核时删除残余分支日志。

可用 `integrate_memory(batches?)` 整理新增记忆，每批最多100条、每次最多20批。它复用现有独立 memory 会话的暂存副本、完成回执、冲突检查和安全提交，不直接给予普通任务修改他人画像的权限。返回处理数与剩余数；需要清空队列可按结果继续调用。任务取消会连带撤销正在进行的整理事务，未成功提交的消息保留在队列中。原有每满100条自动学习仍然可用，两者共用锁避免重复整理。

新闻默认通过原生联网搜索核实日期和来源；未指定关注点时，结合当前会话公开讨论与可验证兴趣选题。不能借共享历史泄露其他群或私人聊天的信息；搜索失败应如实说明。

## Admin 管理

admin 可以查看、查找、按类型筛选全部会话任务，创建、编辑、暂停、启用或删除任务，查看下次时间及最近执行结果。固定消息正文可使用 `[CQ:at,qq=123456]`，只将这种艾特标记转换为原生 at，其他文字作为文本保存。

AI任务支持三种发送模式：

- `auto`：默认，按提示词决定；新闻/提醒应该发送，维护任务可以静默。
- `message`：完成后向绑定会话交付结果。
- `silent`：宿主硬性禁止文字、聊天记录和文件发送，适合内部维护。

admin创建AI任务默认使用普通权限，请按需填写真实执行者QQ。越界操作需要明确勾选主人授权，且执行者必须是当前绑定的主人；主人授权的私聊任务只能绑定主人本人的私聊。固定消息不需要主人授权。

编辑和删除校验版本号，其他人已修改时返回冲突，须刷新后重试。修改、暂停、删除、功能关闭或服务停止都会撤销正在运行的旧任务；已经发送的在途请求及已经写入的文件无法回滚。所有管理接口受现有admin登录保护。

## 持久化、断线与升级

任务及执行回执保存在 `data/timing/tasks.sqlite3`，已有数据不改写；新数据库自动创建，备份时包含整个 `data/` 即可。Docker现有数据挂载已覆盖该目录，无需迁移原有AI人设、记忆或手动增加依赖。

```bash
docker compose up -d --build --remove-orphans
```

调度每秒检查，时间包含秒；这是普通应用调度，网络、模型、负载会造成延迟，不能保证严格实时。固定消息和AI各有4个并发槽，单个任务不重入；每个会话最多保留1000个任务。指定机器人QQ的任务只使用该账号的连接；无连接时等待恢复。

领取任务时先持久记录执行并推进下次时间，再调用QQ或AI，避免重启重复发送。离线错过多个周期只补执行一次，不连续补发所有周期；AI关闭时AI任务等待恢复，固定提醒正常运行。发送回执超时标为unknown，不自动重发；异常退出时未完成的运行也记为unknown，不自动重做本次工作。执行记录滚动保留30天，不保留fork完整对话。

主要代码与提示词入口：

- `src/feature/timing/schedule.py`：北京时间日期规则。
- `src/feature/timing/storage.py`：持久化、领取与执行回执。
- `src/feature/timing/feature.py`：QQ指令、场景权限、工具与调度。
- `src/feature/timing/admin.py`、`panel.html`、`panel.js`：admin接口和界面。
- `src/feature/ai/engine.py` 的 `SCHEDULED_RULES`：定时执行提示词。
- `dsh/plugin.mjs`：原生fork、分支清理与工具注册。
- `src/feature/ai/self_description.md`：机器人必读的整体能力说明。

本地隔离界面预览：`.venv-ai/Scripts/python.exe scripts/preview_timing_admin.py`，打开 `http://127.0.0.1:10012`，只操作 `data/timing-admin-validation/`，不会连接QQ或调用模型。测试使用本地模拟模型和QQ，不替代真实NapCat服务器的发送验收。
