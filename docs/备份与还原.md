# 备份与还原

管理界面的「备份管理」提供生成、列表、下载、删除、导入校验和两种还原模式。使用项目默认启动命令 `python -m src.main`，外层维护进程负责停止机器人、离线处理文件及重新启动。直接用 uvicorn 导入 `src.main` 时，只能管理已有包，自动备份和还原不可用。

## 包含什么

| 内容 | 说明 |
| --- | --- |
| `data/` | 包含各功能配置、主人绑定、管理密码、Pixiv 凭据及其解密密钥、任务数据库、消息原文和媒体解析缓存 |
| `data/ai/workspace/` | 人设、SKILL、用户/群聊记忆、收到和生成的文件以及工作区中的项目 |
| dsh 数据和本地模型 | 对话日志、升级保护数据、嵌入模型缓存与向量索引 |
| 项目配置 | `.env`、`.env.host`（如果存在），以及实际进程中本项目使用的环境变量；Docker/systemd 注入的 API Key 也会保存 |
| `project/` | 当前源码、依赖锁定文件、Docker/原生部署文件、说明与许可证；不带 `.git`、Python 虚拟环境、`node_modules` 等可重新安装的依赖 |

包内 `manifest.json` 记录格式版本、时间、文件大小及 SHA-256。导入和还原会校验整个包，拒绝越界路径、重复文件、特殊文件、包内符号链接及超限内容。上限为 50 万个成员、展开后 100 GiB。工作区模型缓存中的内部文件链接在生成时保存为实际文件；外部链接或目录链接会使备份失败，避免悄悄遗漏数据或读取服务器其他目录。

不包含 `data/backups/`，因此多个备份不会互相嵌套。也不包含操作系统或容器镜像、临时安装到系统的 XeLaTeX 等软件、工作区外的服务器文件、独立的 NapCat 配置与 QQ 登录状态。仅存在于 QQ 远端、尚未下载的附件不能保证在换环境后仍可获取。需要这些内容时应另外保存镜像、系统安装清单或 NapCat 数据。

**包中包含可直接使用的密钥、密码和聊天记录，没有密码加密层。请使用 HTTPS 下载，保存在受限目录，不要上传公共网盘或提交 Git。** 项目不会自动删除历史包；包内旧原文也不会随在线保留期自动消失。

## 在线生成和还原

1. 等正在执行的聊天、Spawn、记忆整理、定时任务、JM/Pixiv 下载及测试完成。媒体解析队列会在停机时保存进度，不需要等所有图片解析完。
2. 点击「生成当前时间的备份」。服务关闭后才开始打包和 SQLite 完整性检查，成功后自动启动；页面会尝试重新连接。大数据集可能需要数分钟，请勿在这期间反复重启容器。
3. 下载并在其他设备保存。备份列表可直接选择还原；外部包先上传并校验，再选择模式及输入确认文字。

还原先在 `data/backups/` 中暂存、校验和合并，空间不足会拒绝。覆盖或增量安装前，自动生成 `before-restore-*.zip`。替换采用事务记录，失败回滚原数据；如果进程在安装过程中被强制结束，下次通过默认入口启动时会先恢复原数据，再初始化功能。

覆盖还原清除现有项目数据并替换为包内数据，保留备份管理目录。增量还原的具体规则是：

- 现有独有目录、文件、数据库记录保留。
- 项目管理的 JSON 配置/状态、AI YAML 配置按字段递归合并；同字段以备份为准，数组整体替换。工作区普通项目文件按同路径整文件冲突处理。
- 数据库以包内版本为基础，追加当前独有记录；主键或唯一索引冲突保留包内记录。聊天按消息身份匹配，重新分配当前独有消息的序号，同步修正媒体任务和补充队列的引用。表结构不同、没有可靠主键或不适合合并的虚拟表会拒绝增量还原，原数据不变。
- Markdown、人设、图片、PDF、同一段 dsh JSONL 对话日志等同路径冲突，使用包内整个文件。不会尝试逐行拼接记忆或对话日志。
- 向量索引是派生数据，合并后从记忆源文件重新建立，本地模型缓存保留。

安装完成后所有功能重新初始化，管理密码和主人绑定以还原结果为准。备份中的有效项目环境变量保存到 `data/.deployment-environment.json`，默认入口会优先加载它们。之后如果要重新由 Docker/systemd/`.env` 控制这些值，可停机后编辑或移除这个文件；它也可能含明文 API Key。

监听地址、端口、公开文件 URL 也可能随包恢复。页面失联时请检查这些值，不要认为一定还原失败。实际对外发送、QQ 撤回等已发生的外部效果不会被撤销，正在执行的任务不能通过还原恢复运行现场。聊天原文启动后仍按 30 天保留规则清理，dsh 会话仍遵守原保留期限；换目录或操作系统可能让 dsh 轮换工作目录绑定的会话，原日志仍在包内，保留的原文会重新供聊天使用。

## 干净环境恢复

使用可信来源的包，并先查看 `manifest.json`。将包内 `project/` 放到新项目目录，它包含备份时的程序版本和部署文件。不要把整个 ZIP 无检查地解压覆盖正在运行的应用。

安装 Python 依赖及 Node.js/dsh 依赖，参考 README 的 Docker 或原生部署说明。将备份 ZIP 放到项目外的一个私有目录，**在机器人尚未启动时**执行：

```bash
python -m src.backup.cli verify /private/backup.zip
python -m src.backup.cli restore /private/backup.zip --mode overwrite
python -m src.main
```

离线还原会自行把包导入备份列表、校验并恢复 `data/` 及有效环境配置，不必手工拼接数据库和密钥。不要先把包内 `data/` 复制进来再重复还原。Docker 部署时，可以先构建镜像，然后运行：

```bash
# 将 backup.zip 放到 ./data/backups/import.zip，数据目录仍按 compose 挂载。
docker compose run --rm myqqbot python -m src.backup.cli restore /app/data/backups/import.zip --mode overwrite
docker compose up -d
```

上述命令的服务名需与 `docker-compose.yml` 一致。还需自行恢复 NapCat、网络、HTTPS 证书和系统软件；确认域名及端口后再对外启用。网页还原只还原数据，不执行 ZIP 中的源码。跨版本还原建议使用包内的对应版本源码部署，再按项目升级流程升级。

停止机器人后也可离线生成备份：

```bash
python -m src.backup.cli create
```

离线命令会检查默认维护进程的文件锁。不要绕开默认入口，另外启动一个机器人实例写入同一个数据目录。

## 反向代理

nginx 默认上传限制通常不足以导入完整备份。可在管理界面的 HTTPS server/location 中根据自己的磁盘及备份大小设置，例如：

```nginx
client_max_body_size 10g;
proxy_request_buffering off;
proxy_read_timeout 600s;
proxy_send_timeout 600s;
proxy_set_header X-Forwarded-Proto $scheme;
```

这些值仅为示例，并不自动改动你的服务器配置。上传前仍需登录管理界面；请保留防火墙与 HTTPS 保护。
