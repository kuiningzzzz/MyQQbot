# 表情库与 Agent 管理

表情库把机器人 QQ 账号的收藏和本地副本分别管理。NapCat 需要支持 `fetch_custom_face_detail`、`add_custom_face`、`delete_custom_face` 和 `set_custom_face_desc`；本次按 NapCat 4.18.38 接口实现。

接口依据：[NapCat 4.18.38 收藏操作源码](https://github.com/NapNeko/NapCatQQ/blob/v4.18.38/packages/napcat-onebot/action/extends/CustomFace.ts)。查询返回原生收藏详情，修改和删除使用资源 ID，不直接用 MD5 删除。

## 如何使用

启动后，机器人在后台同步已连接账号的收藏，通常每小时核对一次。admin 的“AI 服务 → 表情库”可以手动同步、上传图片或从公开 URL 添加，并编辑名称、标签、描述及启用状态。页面支持按账号、关键词和分页查看；“测试发送”会真的向填写的群号或私聊 QQ 号发图，执行前会确认。

普通群友可以让机器人发送已经启用的表情。主人还可以提出：

- “把我刚发的这张图收藏成表情，叫猫猫点赞。”
- “把工作区里的 result.gif 加入表情库，只保存在本地。”
- “给猫猫点赞补上赞同、夸奖两个标签。”
- “停用这张表情。”
- “删除这个表情的 QQ 收藏，本地保留。”

主 Agent 直接使用 `find_sticker` 查询少量候选，再使用 `send_sticker` 发到当前会话。它不需要读取整个目录，也不会在查询时调用视觉模型。发送每轮最多一张，同账号、同会话冷却 10 秒；定时任务的发送也计入正常交付回执。静默定时任务和普通后台执行者不能发送表情。

增删改由主人发起的后台执行者读取内置 SKILL，通过原生命令运行管理脚本。宿主同时验证执行任务、请求者和当前主人身份，任务失效或主人资格撤销后拒绝操作。普通群友不能修改全局收藏，聊天里转述“主人同意了”不能授予权限。admin 使用现有登录认证，预览图片也需要登录。

## QQ 收藏与本地库的区别

名称、标签、本地描述和启用状态只影响机器人选择表情。勾选“同步 QQ 描述”或在脚本中设置 `qq=true`，才会修改 QQ 收藏描述。添加默认同时保存本地和 QQ 收藏，可以选择仅本地。

删除有三种范围：

| 范围 | 结果 |
| --- | --- |
| 本地移除 | 保留 QQ 收藏，本地不可查询、发送；后续同步不会自动重新启用 |
| 仅删 QQ | 删除账号收藏，保留可用的本地图片 |
| 两边删除 | 删除 QQ 收藏并移出本地库 |

在 QQ 客户端手动取消收藏，也不会自动删除机器人本地副本。临时不想使用某张图可以“停用”；需要恢复已移除的表情时重新添加原图片。替换图片使用“添加新图 → 确认成功 → 删除旧图”，QQ 没有本项目可用的原地替换图片事务。

QQ 操作超时或最终状态无法确认时返回 `unknown`，保留待核对记录，禁止自动重放。重新同步后按实际收藏状态解除待核对标记；本地保存成功并不代表 QQ 收藏成功。发送同样只有拿到消息 ID 才算确认，发送成功后的日志错误不会导致重复发送。

## 图片处理和存储

支持 PNG、JPEG、GIF、WebP，单张最多 8 MiB、单帧最多 2000 万像素。图片通过内容去重，下载、OCR、视觉转述在独立后台队列进行，结果写入表情目录。GIF 保留原始文件，理解时只抽样首、中、末帧并说明抽样限制；超过解码量限制的动图会标注失败，仍可查看状态和重试。自动描述只是选择线索，不能保证 OCR、情绪判断完全准确。

重复静态图复用现有媒体缓存，避免聊天图片又作为表情重复理解。手工名称、标签、描述不会被自动标注覆盖。后台失败会有限重试，重启会恢复未完成标注；QQ 写操作不会自动重试。

默认存储位置：

```text
data/ai/.state/stickers.sqlite3          目录、账号归属、同步状态、待核对操作
data/ai/workspace/stickers/assets/       以 SHA-256 命名的原始图片
data/ai/workspace/.agents/skills/
  sticker-management/SKILL.md           部署后可读取的管理说明
  sticker-management/scripts/manage.py 当前执行任务使用的管理脚本
```

本地移除保留禁用标记，未被其他有效条目引用的图片经过一天宽限后定期清理。默认路径下的数据和图片随项目备份恢复；备份不包含外部 NapCat 账号状态，恢复本地备份不会自动重建或删除 QQ 客户端收藏。图片不写进 `memory/`，也不会作为用户画像写入向量索引。

脚本的维护源文件位于 [SKILL.md](../src/feature/ai/skills/sticker-management/SKILL.md)，启动时安装到工作区。通过私有回环桥接调用当前有效任务，不需要 admin 密码。dsh 会清除普通子进程环境里的密钥类变量，因此插件通过原生 `shellEnv` 注册表，为主人发起的执行者和定时分支单独注入 `DSH_QQBOT_CALLBACK` 与 `DSH_QQBOT_STICKER_TOKEN`。后者只允许本任务的表情管理，不能冒用其他任务或调用发送、记忆等其他桥接操作，任务结束、撤销或过期后失效；全局桥接令牌不传入命令子进程，也不写入凭据文件。不要打印环境或把凭据放进聊天、命令参数、请求文件和报告。

更新后需要重启服务，让新插件与工作区脚本一起生效；已有记忆、图片和表情目录不需要清空。脚本会分别提示缺少桥接地址、缺少当前任务凭据、地址错误或任务编号错误。原生 bash/pwsh 调用继承受管环境即可，不要手工填入凭据。QQ 侧失败仍按真实回执处理；`qq=false` 可用于仅保存本地，不能把它当作绕过会话或主人权限的办法。

`AI_STICKERS_ENABLED=false` 或 admin 中的开关可停止自动同步、标注和 Agent 发送；admin 仍可手动整理本地库。

图片添加到 QQ 时，宿主通过 NapCat 的 `download_file` 传递字节，再使用 NapCat 返回的路径调用收藏接口，因此两个容器不必共享图片目录。URL 来源复用现有安全下载器；当前会话附件只允许使用本会话近期登记的附件，文件路径限定为工作区内的实际普通文件。
